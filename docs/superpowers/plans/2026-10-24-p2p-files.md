# P2P 文件 MCP 实施计划

目标：服务端通过 WebRTC 数据通道调用用户电脑上的只读文件代理，不依赖开发环境的 MCP。

方案：独立 Python MCP 服务负责已认证的 SDP 交换及 MCP 工具；本地 Python 代理主动建立 WebRTC，首次明确指定授权目录，配置保存在本地，之后自动恢复连接。使用独立的 MCP Token 与每设备 Token。默认不选择任何目录、不提升权限、不修改文件。STUN/TURN 由部署者配置；TURN 属于加密中继，不承诺所有网络均直连。

- [x] 先写真实双端 WebRTC 与 HTTP MCP 测试，再实现信令、RPC、设备状态、超时及重连。
- [x] 实现本地授权配置命令、环境变量模板、Windows 启动脚本及控制台连接模板。
- [x] 验证未认证请求、目录越界、断线、真实数据通道读取与现有回归测试；编译前端并更新部署说明。

测试只使用临时目录和测试令牌，不授权用户真实目录，不自动安装后台常驻服务。

验证：49 项后端测试、7 项前端单元测试、9 项浏览器测试通过，前端构建通过。文件 MCP 的 9 项测试包括真实数据通道、越界及链接竞态、根目录身份持久化、设备令牌隔离、MCP 错误状态、并发与重新连接。真实设备目录尚未授权，公网 NAT/TURN 未验证。
